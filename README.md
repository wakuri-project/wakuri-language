# Wakuri Language v0.1

**日本語からプログラミングへ、橋をかける。**

日本語で書けるだけでなく、
書きながらプログラミングを学べる、
日本語ネイティブなプログラミング言語。

---

## 30秒で分かるサンプル

```
年齢 を 55 と する

もし 年齢 が 50 以上 なら
    "まだまだいける" を 表示する
そうでなければ
    "まだ若い" を 表示する
終わり
```

```bash
pip install -r requirements.txt
python3 main.py examples/example1.nj
```

```
まだまだいける
```

## この言語の特徴

- 日本語のSOV語順(「対象 → 動作」)で読めるコードが書ける
- 「やさしい構文」と「学習構文」を、意味レベルで分けて使い分けられる
- 間違えたとき、単なるエラーではなく教育的な説明が返ってくる
- インデントに文法上の意味を持たせない(`終わり`だけがブロックの区切り)
- 記号(`>=`)と日本語(`以上`)、どちらの比較表現も使える
- 最終的にPythonコードへ変換され、実行される

## やさしい構文と学習構文

この言語には、値を名前に結びつける書き方が2つあります。単なる別表記ではなく、**意味そのものを分けています**。

```
# ① やさしい構文(SetValue): 無ければ作る、あれば更新する
年齢 を 55 と する

# ② 学習構文(DeclareVariable): 新しい変数を明示的に宣言する
変数 年齢 = 55
```

| 書き方 | 呼び方 | 意味 |
|---|---|---|
| `年齢 を 55 と する` | SetValue | 現在のスコープに「年齢」が無ければ作り、あれば更新する |
| `変数 年齢 = 55` | DeclareVariable | 現在のスコープに新しい変数を明示的に宣言する |

Pythonなどでは `x = 5` のような代入によって名前が作られ、その後も同じ記法で値を更新します。この言語ではこの2つをあえて分けることで、「新しく作ること(宣言)」と「値を変えること(代入)」の違いそのものを学習に利用しています。

はじめてプログラミングに触れる人は、「変数」「宣言」「代入」といった専門用語を知らなくても `年齢 を 55 と する` から書き始められます。一般的なプログラミングの考え方に興味が出てきたら `変数 年齢 = 55` を使ってみてください。

## エラーが先生になる

同じスコープで `変数` を使って二度宣言すると、次のように教えてくれます。

```
変数 年齢 = 55
変数 年齢 = 60   # 同じ名前をもう一度「宣言」してしまった
```

```
--- error ---
二重宣言エラー(行2)
「年齢」はすでに作られています。
値を変更したい場合は
    年齢 を ... と する
と書けます。
学習メモ: 新しく変数を作ることを「宣言」、既存の値を変更することを「代入」と呼びます。
```

内部的には、この処理は2つの層に分かれています。

1. **意味チェック層**が「何が起きたか」(種類・行番号・対象など)という客観的な事実だけを見つける
2. **教育・表示レイヤー**が、その事実を人間向けの文章に変換する

この2つを分離しているのは、将来「初心者向け」「経験者向け」など、同じ間違いでも複数のトーンで説明を出し分けられるようにするためです(v0.1では初心者向けの文章のみを使います)。

## 3つのコア思想

### 1. 言語そのものが学習者を導く
エラーは失敗の通知ではなく、学びの機会として扱います。意味チェック層が見つけた「何が起きたか」を、教育・表示レイヤーが「次にどう書けばいいか」まで含めて伝えます。

### 2. 日本語構文から、一般的なプログラミング概念へ橋をかける
「やさしい構文」から入り、必要になったら「学習構文」を使う。その過程で、変数・宣言・代入・スコープ・比較といった、他の多くのプログラミング言語にも共通する概念に自然に触れられるようにします。

### 3. 日本語の語順・助詞を、意味を持つ構造として活用する
`〜を` `〜と` `〜とする` のような助詞の組み合わせを、読みやすさのための飾りではなく、プログラムの意味を構成する技術的な土台として使っています。ただしこれは「この言語だけの発明」ではありません。助詞を引数の役割として使う考え方には、プロデルなど先行する日本語言語に実装例があります。この言語では、日本語ネイティブな構文を成立させるための基盤として位置づけています。

## v0.1でできること

- 数値(整数・小数)・文字列・負の数
- `年齢 を 55 と する`(SetValue)
- `変数 年齢 = 55`(DeclareVariable)
- 変数参照
- `式 を 表示する`(SOV型の表示構文)
- 四則演算(`+ - * /`)
- 比較(記号形式 `>= <= > < == !=` / 日本語形式 `以上 以下 より大きい 未満 と等しい と等しくない`)
- 条件分岐(`もし〜なら`、`そうでなければ`、入れ子、`終わり`)
- コメント(`#`)
- 教育的な二重宣言エラー・未定義名エラー(コンパイル時)
- 構文エラーの行・列表示
- Pythonコードへの安全な変換(予約語との衝突を避ける内部名変換)

## まだできないこと

- 繰り返し(ループ)
- 関数
- リスト・辞書などのコレクション
- ファイル・CSV操作
- Pythonライブラリの直接利用
- Web開発向けの機能
- 日本語学習モード(思想としては採用済み。仕組みの土台のみ用意)
- エディタ連携・LSP
- Python以外へのバックエンド変換

## 既知の制約

正直に書きます。

1. **一部の実行時エラーは、まだPythonの生のエラーがそのまま出ます。**
   `10 / 0` のようなゼロ除算や、`"文字列" + 5` のような型の組み合わせが原因で起きるエラーは、意味チェック層では事前に検出されず、実行時にPython標準のエラーメッセージが表示されます。教育的なエラー表示は、今のところ**コンパイル時**に分かる二重宣言・未定義名に限られます。

2. **一部の日本語比較フレーズは、内部にスペースを入れられません。**
   `以上` `以下` `より大きい` `より小さい` `未満` `と等しい` `と等しくない` は、1つの決まった言い回しとして扱われるため、途中にスペースを入れると構文エラーになります。

   ```
   ○ 年齢 が 50 より大きい なら
   ✕ 年齢 が 50 より　大きい なら
   ```

   一方、SetValueの `と する` は2語に分けて書けます(`年齢 を 55 と する`)。この違いは今のところ言語仕様上の非対称です。

## 主な先行例との方向性の違い

なでしこ・プロデル・言霊(Kotodama)など、すでに優れた日本語プログラミング言語がいくつも存在します。これらには、自然な日本語表現、助詞を利用した引数指定、教育利用、実用的な自動化など、多くの先行する知見があります。

各言語にはそれぞれ異なる目的・教育機能があります。以下の比較は優劣ではなく、本プロジェクトが特に重視している点を示すものです。

| 観点 | 調査した主な先行例 | この言語が重視している点 |
|---|---|---|
| 主な重点 | 実用的な処理の自動化・自然な日本語記述 | プログラミング概念の理解・学習 |
| エラーの役割 | 各言語の方針に応じた日本語でのエラー通知・説明 | 修正方法や一般的なプログラミング概念の学習まで、診断の主要目的として設計 |
| 値の割り当て | 言語ごとに複数の日本語的表記や代入方式がある | SetValueとDeclareVariableを、表記だけでなく意味レベルで分離 |
| 次のステップ | その言語の中で完結することも多い | Python等、一般的な言語への橋渡しを意識 |

## プロジェクト構成(開発者向け)

```
grammar.lark        文法定義(Earleyパーサー用)
ast_nodes.py         独自ASTノード定義(SourceSpan付き)
parser.py             Lark Parse Tree → 独自AST への変換
semantics.py           意味チェック層(Diagnosticの生成のみ、文章は持たない)
display.py               教育・表示レイヤー(Diagnosticを文章に変換)
codegen.py                独自AST → Pythonコード生成
main.py                    CLIエントリポイント
check_ambiguity.py          文法の曖昧性を機械的に監視する開発用スクリプト
test_v01.py                  自動テストスイート
examples/                     サンプルコード一式
```

処理の流れ:

```
日本語コード
  → Parser(Lark, Earley)
  → Lark Parse Tree
  → 独自AST(SourceSpan付き)
  → 意味チェック層 → AnalysisResult(diagnostics / annotations)
  → 教育・表示レイヤー(エラー時)
  → Python Generator
  → Python
  → 実行
```

パーサーにはLarkのLALRではなくEarleyを採用しています。「NAME を」で始まる文がSetValueなのかPrintなのか、1トークンの先読みでは判別できないためです。助詞主導の日本語文は今後も同種の曖昧さが増える見込みのため、最初からEarleyを選んでいます。曖昧な解釈が紛れ込んでいないかは `check_ambiguity.py` で監視しています。

## ロードマップ・将来構想

まだ実装順は確定していません。現時点で検討している候補です。

- 繰り返し・関数
- リスト・辞書などのコレクション
- ファイル・CSV操作
- 実行時エラーの教育的診断(ゼロ除算・型不一致など)

- Web Playground
- 他の一般的なプログラミング言語への学習ブリッジ(日本語コードとPython/JavaScript等の対訳表示など)

現時点の主な対象は、**日本語話者が日本語を入口にプログラミングを学ぶこと**です。日本語学習への応用は将来構想として保持していますが、コアの文法を変える予定はありません。
